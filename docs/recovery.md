# 本地修改与中断恢复

目标技能目录中的 `.skillhub-state.json` 记录来源、版本、依赖和内容校验值；不要把它当作密码库。安装写入使用 `.skillhub-lock` 互斥目录。

常规异常会回滚已经移动的文件。进程被杀或断电不能保证自动回滚，因此保留 `.skillhub-txn-*`：

- `previous-state.json`：操作前的管理状态。
- `plan.json`：目标路径及本次动作。
- `old/<name>`：被移动的原技能。
- `new/<name>`：尚未安装的暂存版本。

遇到中断时，先停止对该目标的所有写入，确认没有活跃 Skillhub 进程；运行 `doctor --dir <目标>` 并检查事务目录。将当前目标和恢复文件先完整备份，再根据 plan 对每个技能比较目标、old 和 new，决定完成安装或恢复旧版。恢复旧版时将 old 中的内容移回目标，并恢复 previous-state；本次新安装的目录仅在确认来源后移走。最后移走已处理的事务目录和锁，重新运行 doctor。

不要只删除锁就继续写入。无法确认中断阶段时，保留现场并人工处理。

`--force` 导致的主动覆盖会返回 `.skillhub-backup-*` 路径，其中 old 保留覆盖前的文件。备份不自动清理；确认不再需要后由维护者删除。单技能恢复可从备份复制回来，但内容将与当前状态的校验值不一致；用 doctor 确认并将需要保留的改动同步回源码，再正常更新。
